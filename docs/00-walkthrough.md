# 00 · 从哪里开始，每一步做到什么程度

别一次复制整页命令。下面按顺序走：**做一步、检查一步，符合“通过标准”才继续。** 这是特定 MU3356 / B28 构建的实测记录，不是所有 F50 Pro 的通用刷机方案。

## 第 1 步：先确认机器和工具 🟢

**准备什么：** Windows 电脑、稳定的数据线和供电、足够空间、另一份离线备份介质；可信的 ADB、spd_dump、Zadig，制作镜像还需要 Python、LZ4 和匹配的 Magisk 输入。

**怎么做：** 先确认型号 MU3356、Android 15、完整固件号和构建日期。能用 ADB 就读取属性；不能用就按第 1、2 章从备份里的属性文件确认。用短英文路径分开放 `backup-new`（原件）、`raw`（完整 TrustOS）、`derived`（修改产物）、`readback`（回读）。

**通过标准：** 与首页列出的完整构建相符，工具来源和哈希有记录。仅仅写着“B28”不够。

**⛔ 先停：** 型号、构建不一致，或拿不准工具来源。不要为了匹配教程而降级、恢复出厂或解锁。

## 第 2 步：只给下载接口装驱动 🟡

**怎么做：** 按[第 1 章](01-backup.md)确认短暂出现的 `1782:4D00`，只给这个下载接口装 WinUSB。先启动下载器等待，再冷 USB 重连。

**通过标准：** 下载器确实连接到目标设备，可以读取分区表。没有这个硬件 ID 就不继续。

**风险 / 失败怎么办：** 装错驱动会让正常网卡或 MTP 失效。不要对整个复合设备、RNDIS/NCM 或别的手机改驱动；不要猜短接点。连接不稳定先查线和供电，不进入刷写。

## 第 3 步：先把原件读出来 🟢

**怎么做：** 按[第 1 章第 3 节](01-backup.md#3-读取分区表与全部目标分区)运行备份命令，保存分区表、原始回执和每个文件的 SHA256。再运行离线校验工具，复制到第二介质并重新核对。

**通过标准：** 每个目标都有完整读取回执和文件；本案是 80 个目标。`r all` 不含 userdata/cache/blackbox，用户数据另外备份。

**风险 / 失败怎么办：** 备份包含设备身份和校准，别发群或上传网盘公开链接。缺文件、回执不完整或哈希不一致就停，不能只看“文件很多”。

## 第 4 步：核对活动槽，补齐完整 TrustOS 🟢

**怎么做：** 按第 1 章第 4、5 节核对下载器与 misc CRC；能启动后还要核对 Android 槽位。把 TrustOS 头尾分开读，再用 `assemble_trustos.py` 组合。

**通过标准：** 本案是 A 槽；完整 TrustOS 恰好 6 MiB，头部、裁剪签名镜像前缀和长度全部通过检查。保留最初分区备份和这份完整 raw，不能二选一。

**⛔ 先停：** 槽位不同、CRC 不对、缺尾部或大小不同。不能靠补零、切 B 槽解决，也不能拿别人机器的 TrustOS 顶上。

## 第 5 步：离线准备 root 镜像 🔴

**怎么做：** 完整阅读[第 2 章](02-offline-build.md)。在副本上处理 ramdisk、Magisk 文件、自己的 ADB 公钥和 AVB 布局。每个修改都要能解释，压缩解压回环与原厂恢复模拟都要通过。

**通过标准：** 原件未动；结构检查、恢复模拟、长度、哈希和修改范围已审查；启动脚本不会泄露私钥或放开陌生主机认证。

**⛔ 重要限制：** 仓库没有完整 root 镜像生成器，参考 APK 的精确来源/签名也尚未完全闭环。第 2 章是实现规范，不是“执行一下就出包”的命令。**不会独立制作和审查，就停在备份阶段，先别刷。**

## 第 6 步：人工刷入并完整回读 🔴

**怎么做：** 按[第 3 章](03-flash-verify-rollback.md)的写前清单逐项确认。命令一条条执行，等完成回执和 `FDL2 >`，完整回读并比对后才重启。

**通过标准：** init_boot 的完整 8 MiB 与待写镜像一致；涉及 TrustOS 时完整 6 MiB 与“派生前缀 + 原始物理尾部”预期一致。

**风险 / 失败怎么办：** 写错分区、文件或槽位会无法开机。本案 init_boot-only 失败后先恢复原件；不是要求你为了复现故障故意刷一次失败镜像。是否需要 TrustOS 必须单独评估，不凭一个 USB 现象下结论。回读不符或启动失败按第 3 章停下并恢复，别扩大刷写范围。

## 第 7 步：确认是真的 root 🟢 / 重启 🟡

**怎么做：** 执行第 3 章的 ADB 检查，只针对 `$Target`。确认 `boot_completed=1`、固件、`_a`、`uid=0(root)`、Magisk 版本、runtime 文件和启动日志。然后正常重启一次，重连后重查，并比较 live 分区哈希。

**通过标准：** 重启前后均通过；不是网页打开就算 root。只测一次正常重启不代表断电、OTA 或长期稳定性通过。

**⛔ 先停：** ADB、root 或分区哈希异常。不要在设备还不稳定时安装后台或导入插件。

## 第 8 步：安装并验收高级后台 🟡 / Root 桥 🔴

按[第 5 章](05-advanced-backend.md)依次完成：下载核验 → 确认目标 → 安装 APK → 首次初始化 → 配置登录 → 按需设置最小 Root 桥 → 自启 → 正常重启验收。

**通过标准：** 页面可访问、登录正常、未登录的敏感 API 被拒绝；需要 Root 功能时只执行 `id` 验证；重启后再检查一次。原厂后台和基本网络也要能用。

**风险 / 失败怎么办：** HTTP 没有传输加密，Root API 能改系统。不要暴露公网、别重置现有口令、别为排障开启无认证终端。网页能开但 Root 功能不通，按第 5 章分层查，不重新刷机。
